## Bug
1. Clicking `+` always creates a brand-new consultation, even when an empty one is already active. → duplicates.
2. `+` eagerly writes a `conversations` row + `mind_maps` row to Supabase before the user types anything → orphaned empty chats.

## Root cause
`Sidebar.handleNewChat` → `store.createNewConversation` (`lib/store.ts:168-207`) unconditionally INSERTs into Supabase on click. The chat edge function already supports creating the conversation server-side when no `conversationId` is sent (`supabase/functions/chat/index.ts:133-155`), deriving the title from the first message and seeding `mind_maps`. The client already handles the server-created conversation via the `X-Conversation-Id` header path in `ChatPanel.handleSendMessage` (`ChatPanel.tsx:126-134`).

## Approach (ponytail: reuse the server path, add a local-only draft)
Introduce a local **draft** state — never written to the DB — and let the first message turn it into a real conversation through the existing server path. This fixes both symptoms with one change, no new abstractions.

### 1. `lib/store.ts`
- Add state: `draftConversation: Conversation | null`.
- Add action `startDraftConversation()`:
  - If `draftConversation` exists → reuse: `set({ activeConversationId: draftConversation.id })`. (dedupe)
  - Else if the current `activeConversationId` is a real conversation with no messages (`messages[activeConversationId]?.length === 0`) → reuse it, do nothing. (dedupe: clicking `+` on an already-empty real consult keeps it)
  - Else → create a local draft: `{ id: "draft", title: "New Consultation", updatedAt: "Just now" }`, set `draftConversation`, `activeConversationId = "draft"`, seed `messages["draft"] = []`.
- Add action `clearDraft()`: `set({ draftConversation: null })`.
- Update `selectConversation(id)` to also clear the draft when switching to a different conversation (selecting a real consult abandons the unsaved draft): `set(state => ({ activeConversationId: id, draftConversation: state.draftConversation?.id === id ? state.draftConversation : null }))`.
- **Delete** `createNewConversation` and its interface entry — it becomes dead code (`Sidebar` was the only caller). The server-side chat function path replaces it.

### 2. `components/ui/Sidebar.tsx`
- Replace `handleNewChat` body with: `startDraftConversation(); setActivePane("chat");` (no async, no DB, no title calc, no `userId`/`getToken`).
- Conversation list rendering: `const list = draftConversation ? [draftConversation, ...conversations] : conversations;` then `map` over `list`. Active highlight `conv.id === activeConversationId` already handles the draft id `"draft"`.

### 3. `components/chat/ChatPanel.tsx`
- In `handleSendMessage`: detect draft — `const isDraft = tempConvId === "draft"`. Send `conversationId: isDraft ? undefined : tempConvId`. The server then creates the real conversation. In the existing `if (returnedConvId && returnedConvId !== tempConvId)` branch, add `clearDraft()` alongside the `fetchConversations` + `selectConversation` already there.
- In the load-on-conversation-change effect (`Lines 50-56`): skip DB fetches for the draft — `if (activeConversationId && activeConversationId !== "draft") { fetchMessages(...); fetchMindMap(...); } else if (activeConversationId === "draft") { resetLocalMindMap(); }` to avoid stale nodes from the previous conversation showing in the mind-map pane.

### 4. `lib/mindmapStore.ts`
- Add tiny action `resetLocalMindMap()`: `set({ nodes: [], edges: [], selectedNode: null, drawerOpen: false })` — no DB write. Used by ChatPanel to blank the canvas for a fresh draft.

## Why this is the lazy/correct fix
- One root-cause change in the shared `store` action guards every caller of `+`.
- Reuses the existing server-side conversation-creation path (already correct, already tested by the no-`conversationId` flow) — zero new server code.
- Drafts vanish on reload (in-memory only) per your choice; nothing changes server-side until the first message.

## Skipped / when to add
- No localStorage persistence for drafts — add only if you want unsaved drafts to survive reload (you chose not to).
- No explicit cleanup of any pre-existing orphaned empty rows already in the DB from before this fix — add a one-off SQL purge if they're cluttering the list.

3. Manual: click `+` → empty consult appears in sidebar as "New Consultation"; click `+` again → no duplicate (still the same one). Reload → draft gone.
