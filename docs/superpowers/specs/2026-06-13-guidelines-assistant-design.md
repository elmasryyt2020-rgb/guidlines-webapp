# Guidelines Assistant: Technical Specification & Prompts

This document outlines the architecture, database schema, API design, and frontend design system for the Medical Guidelines Assistant. It also provides the exact prompt sequence for building this application chat-by-chat, prioritizing the UI-first sequence.

---

## 1. Project Overview & Architectural Goals

The **Guidelines Assistant** is a web-based clinical chatbot and interactive brainstorming system designed for Egyptian medical doctors. It utilizes the clinical guidelines published by the Ministry of Health of Egypt (located in the `./ENT` folder as PDFs) to answer medical questions, assist in differential diagnosis, and brainstorm diagnostic/treatment plans using a visual, interactive node-based mind map.

### Technology Stack
*   **Frontend**: Next.js (App Router, TypeScript, Tailwind CSS, React Flow)
*   **Authentication**: Clerk (User sign-in, session management)
*   **Database**: Supabase PostgreSQL with `pgvector` extension (768-dimensional vectors)
*   **AI Engine**: Gemini (via Deno-compatible SDK in Supabase Edge Functions, and Google SDK in local ingestion scripts)
    *   **Embeddings Model**: `text-embedding-004` (768-dimensions)
    *   **Chat & Generation Model**: `gemini-2.5-flash`
*   **API Layer**: Supabase Edge Functions (Deno-based serverless endpoints)
*   **Ingestion Pipeline**: Local Node.js script (`npm run ingest`) running once to populate the database.

### Design Style (Neo-Brutalism)
The UI design is inspired by the Neo-brutalist style represented in the root screenshot files. Key visual guidelines:
*   **Borders**: Solid, pure black borders (e.g., `border-[3px] border-black` or `border-4 border-black`).
*   **Shadows**: Rigid, zero-blur offsets: `shadow-[4px_4px_0px_0px_rgba(0,0,0,1)]` or `shadow-[6px_6px_0px_0px_#000]`.
*   **Colors**: Pure white backgrounds for panels, accented by bright solid blocks of color:
    *   **Primary/Lime Green**: `#A3E635` (Tailwind `lime-400`)
    *   **Pink/Magenta**: `#D946EF` (Tailwind `fuchsia-500`)
    *   **Vibrant Cyan**: `#06B6D4` (Tailwind `cyan-500`)
    *   **Sun Yellow**: `#FACC15` (Tailwind `yellow-400`)
*   **Animations**: Hover-translate actions that offset the card/button in the opposite direction of the shadow, simulating a physical press on hover/active states.
*   **Typography**: Bold high-impact display font (`Plus Jakarta Sans` or `Outfit`) paired with extremely clean, readable, clinical body typography (`Inter`) to make the guidelines and diagnoses professional and clear.
*   **No Emojis**: Avoid emojis completely. Represent clinical metrics and system actions with clean stroke icons (e.g. `lucide-react`) styled with black borders or solid color background circles.

## 2. Database Schema (Supabase SQL)

Deploy the following schema to Supabase to enable vector search, conversation tracking, and mind map persistence:

```sql
-- Enable the pgvector extension for similarity search
create extension if not exists vector;

-- Table to store processed PDF guideline chunks and their embeddings
create table public.guideline_chunks (
    id uuid default gen_random_uuid() primary key,
    file_name text not null,                -- Source PDF name (e.g. 'Acute Otitis Externa.pdf')
    content text not null,                  -- The plain text of this specific chunk
    chunk_index int not null,               -- Ordering index within the document
    embedding vector(768),                  -- 768-dim vector generated by Gemini text-embedding-04
    created_at timestamp with time zone default timezone('utc'::text, now()) not null
);

-- Index for fast cosine similarity search on embeddings
create index guideline_chunks_embedding_idx 
on public.guideline_chunks 
using hnsw (embedding vector_cosine_ops);

-- Table to manage chat sessions
create table public.conversations (
    id uuid default gen_random_uuid() primary key,
    user_id text not null,                  -- Clerk user ID (sub)
    title text not null default 'New Conversation',
    created_at timestamp with time zone default timezone('utc'::text, now()) not null,
    updated_at timestamp with time zone default timezone('utc'::text, now()) not null
);

-- Table to store messages in each conversation
create table public.messages (
    id uuid default gen_random_uuid() primary key,
    conversation_id uuid references public.conversations(id) on delete cascade not null,
    role text not null check (role in ('user', 'assistant')),
    content text not null,
    created_at timestamp with time zone default timezone('utc'::text, now()) not null
);

-- Table to store saved mind map node graphs associated with conversations
create table public.mind_maps (
    id uuid default gen_random_uuid() primary key,
    conversation_id uuid references public.conversations(id) on delete cascade not null,
    nodes jsonb not null,                    -- Stores the array of React Flow nodes
    edges jsonb not null,                    -- Stores the array of React Flow edges
    created_at timestamp with time zone default timezone('utc'::text, now()) not null,
    updated_at timestamp with time zone default timezone('utc'::text, now()) not null
);

-- SQL Helper for similarity searches
create or replace function match_guidelines (
  query_embedding vector(768),
  match_threshold float,
  match_count int
)
returns table (
  id uuid,
  file_name text,
  content text,
  similarity float
)
language sql stable
as $$
  select
    guideline_chunks.id,
    guideline_chunks.file_name,
    guideline_chunks.content,
    1 - (guideline_chunks.embedding <=> query_embedding) as similarity
  from public.guideline_chunks
  where 1 - (guideline_chunks.embedding <=> query_embedding) > match_threshold
  order by (guideline_chunks.embedding <=> query_embedding) asc
  limit match_count;
$$;

-- Enable Row Level Security (RLS)
alter table public.conversations enable row level security;
alter table public.messages enable row level security;
alter table public.mind_maps enable row level security;

-- RLS Policies: Restrict access to owners
create policy "Users can manage their own conversations" 
on public.conversations for all 
using (auth.uid() = user_id);

create policy "Users can manage messages in their conversations" 
on public.messages for all 
using (
    conversation_id in (
        select id from public.conversations where user_id = auth.uid()
    )
);

create policy "Users can manage mind maps in their conversations" 
on public.mind_maps for all 
using (
    conversation_id in (
        select id from public.conversations where user_id = auth.uid()
    )
);
```

## 3. Ingestion Pipeline (`scripts/ingest.ts`)

A local Node/TypeScript CLI script that parses PDFs from `./ENT` using `pdf-parse`, chunks them into 1,000-character sections with 200-character overlaps, requests embeddings from `text-embedding-004` (768-dimensions), and writes them to the `guideline_chunks` table in Supabase.

---

## 4. API Endpoints (Supabase Edge Functions)

### Chat API (`/functions/v1/chat`)
1.  Verifies the Clerk JWT token.
2.  Generates the embedding for the user message.
3.  Calls `match_guidelines` on Supabase to fetch context.
4.  Fetches previous messages in the conversation from the `messages` table.
5.  Sends context and history to `gemini-2.5-flash`.
6.  Saves messages to the database and streams the text response.

### Brainstorm API (`/functions/v1/brainstorm`)
1.  Verifies authentication.
2.  Retrieves chat transcript and guideline search context.
3.  Asks Gemini to output a structured JSON structure representing a diagnostic mind map tree:
    *   **Nodes**: `{ id: string, type: 'symptom' | 'differential_diagnosis' | 'diagnostic_test' | 'treatment_plan', position: { x, y }, data: { label, description, guidelinesSource } }`
    *   **Edges**: `{ id: string, source: string, target: string }`
4.  Saves the mind map state into the `mind_maps` table.
5.  Returns the updated React Flow state.

## 5. UI Layout Design

*   **Split Screen (Desktop)**:
    *   **Left Pane (40%)**: Chat Panel. Renders messages as high-contrast speech boxes with 3px black borders and zero-blur flat drop shadows. Avoids emojis; utilizes clean outline medical icons.
    *   **Right Pane (60%)**: Mind Map Workspace. Integrated React Flow canvas rendering nodes as Neo-brutalist cards styled with colored backgrounds (Lime Green, Hot Pink, Cyan, Yellow) based on node types, all sporting thick black outlines and offset shadows. Clicking a node opens a side drawer detailing clinical instructions from the Egyptian MOH guidelines.
